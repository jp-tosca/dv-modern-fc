## Summary

The new frontend handles the simple publish-blocked case correctly — a dataset whose immediate parent collection is unpublished gets legacy's exact "Would you like to publish both right now?" prompt. But it misses the other two cases legacy distinguishes: when **two generations** of ancestors are unpublished it still offers to publish "both", naming only the immediate parent; and when **a collection** whose parent is unpublished is published, the SPA shows a generic confirmation with no warning at all.

## Legacy JSF behavior

Legacy has three distinct messages:

| Case | Legacy string |
| --- | --- |
| Dataset, parent unpublished, user can publish it | `dataset.mayNotPublish.both`: "This dataset cannot be published until {0} is published. Would you like to publish both right now?" |
| Dataset, **two** generations unpublished | `dataset.mayNotPublish.twoGenerations`: "This dataset cannot be published until {0} **and {1}** are published." |
| Dataset, parent must be published by someone else | `dataset.mayNotPublish.administrator`: "This dataset cannot be published until {0} is published by its administrator." |

And for collections: `dataverse.publish.failed` ("Cannot publish dataverse.") with `dataverse.publish.failed.tip` — "This dataverse cannot be published because the dataverse it is in has not been published."

### Steps to observe

1. Log into the legacy JSF app (http://localhost:8080) as `dataverseAdmin`.
2. Create an unpublished collection inside another unpublished collection, and a dataset inside the inner one.
3. Attempt to publish that dataset and observe the two-generations message naming both ancestors.
4. Attempt to publish the inner collection and observe the "cannot be published because the dataverse it is in has not been published" notice.

## New frontend behavior

**Two generations (dataset).** With `Root > QA Test Collection (unpublished) > Gap Review Subcollection 184 (unpublished) > dataset`, the SPA's Publish Dataset modal says only "This dataset cannot be published until **Gap Review Subcollection 184** is published. Would you like to publish both right now?" — the `.both` variant. It names one ancestor and offers to publish "both", although two ancestors are unpublished, so accepting cannot succeed as described.

**Collection.** Publishing `Gap Review Subcollection 184`, whose parent `QA Test Collection` is unpublished, opens a Publish Collection modal reading only "Are you sure you want to publish your collection? Once you do so it must remain published." — no mention that the parent is unpublished and no equivalent of legacy's blocked-publish notice.

### Steps to reproduce

1. Log into the modern frontend (http://localhost:8000/modern) as `dataverseAdmin`.
2. Open the dataset at `/modern/datasets?persistentId=doi:10.5072/FK2/SSQN4W&version=DRAFT` (inside two unpublished collections).
3. Publish Dataset -> Publish, and observe the single-ancestor "publish both" wording.
4. Open `/modern/collections/gap-review-sub-184` and click Publish; observe the generic confirmation with no unpublished-parent warning.

## Expected behavior

- A dataset with more than one unpublished ancestor should say so and name them, rather than offering to publish "both".
- A dataset whose parent can only be published by someone else should say that, as legacy's `administrator` variant does.
- Publishing a collection whose parent is unpublished should warn, and either offer to publish the chain or explain why it cannot proceed — not present a plain confirmation.

## Current behavior

Only the single-parent dataset case is handled. The other cases either show misleading wording (two generations) or no warning at all (collection), so a user can confirm an action whose stated effect is wrong.

## Acceptance criteria

- [ ] A dataset with two or more unpublished ancestors reports all of them and does not offer a "publish both" action that cannot succeed
- [ ] A dataset whose ancestor must be published by another user gets the administrator variant of the message
- [ ] Publishing a collection whose parent is unpublished warns before the confirmation, matching legacy's blocked-publish notice
- [ ] The existing single-parent dataset case keeps its current wording and behavior
- [ ] Covered by automated tests for the two-generations and collection cases
