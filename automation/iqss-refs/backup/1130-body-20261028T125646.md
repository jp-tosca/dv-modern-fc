## Summary

Legacy JSF gives superusers a "Manage Users" page listing every account in the installation, with search, sorting, pagination, a per-user superuser toggle (with a confirmation step) and a "Remove All" action for a user's role assignments. The new frontend has no user administration at all — no route, no component, no strings — and no dashboard from which to reach one.

## Legacy JSF behavior

`dashboard-users.xhtml` renders a "Search these users..." box, a Sort control, and a table with ID, Username, Name, Email, Affiliation, Authentication, Roles (each row carrying a "Remove All" button) and a Superuser checkbox. Toggling the Superuser checkbox raises a confirmation dialog that can be cancelled. The list paginates for larger installations, and Sort offers ascending/descending variants per column (ID, Username, Last Name, First Name, Email, Affiliation, Superuser).

### Steps to observe

1. Log into the legacy JSF app (http://localhost:8080) as a superuser (`dataverseAdmin`).
2. Open the dashboard and click "Manage Users" on the Users card, or go to `/dashboard-users.xhtml`.
3. Observe the user table with the search box, Sort control, Roles / "Remove All" column and Superuser checkbox.

## New frontend behavior

There is no user-administration UI in the SPA. Searching `src/` and `public/locales/` for `manageUsers`, `dashboard-users`, superuser toggling or an admin user list returns nothing; the only `superuser` references are read-only checks that adjust what the current user sees (`Collection.tsx`, `PublishDatasetModal.tsx`, `MyDataItemsPanel.tsx`). `Route.enum.ts` has no users-administration route.

### Steps to reproduce

1. Open the modern frontend (http://localhost:8000/modern).
2. Note there is no dashboard entry for a superuser (see jp-tosca/dv-modern-fc#5).
3. Navigate directly to http://localhost:8000/modern/dashboard/users.
4. Observe the redirect to `/modern/404` — the route is not registered.

## Expected behavior

A superuser should be able to administer accounts from the new frontend: list users with their identifier, name, email, affiliation and authentication provider, search and sort the list, page through it, grant or revoke superuser status behind a confirmation, and revoke a user's role assignments — with the same superuser-only gating as legacy.

## Current behavior

Absent. No route, no component, no i18n strings, no placeholder. The backend already exposes `/api/admin/list-users` and the superuser-toggle endpoints, so only the UI is missing; administrators must use the legacy JSF page or the API.
