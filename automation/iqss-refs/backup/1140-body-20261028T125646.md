## Summary

Legacy JSF exposes a "Widgets" tab on a collection's Theme + Widgets page that gives collection administrators copy-and-paste embed snippets — a Dataverse Search Box widget and a Dataverse Listing widget — for putting the collection on an external website. The new frontend has no widgets UI at all: the single "Theme + Widgets" entry in the collection Edit menu opens the "Not Implemented" modal, so the embed code cannot be obtained from the SPA.

## Legacy JSF behavior

`themeAndWidgetsFragment.xhtml` renders a `widgetsTab` beside the Theme tab. For a **published** collection it shows an informational tip linking the User Guide, then two read-only textareas containing `<script id="dataverse-widget-js" src=".../resources/js/widgets.js?alias=<alias>&...">` snippets — one with `widget=search`, one with `widget=iframe&heightPx=500` — plus a "Done" button. For an **unpublished** collection the tab instead shows a "Why Use Widgets?" / "How To Use Widgets" explainer telling the user to publish first.

### Steps to observe

1. Log into the legacy JSF app (http://localhost:8080) as `dataverseAdmin`.
2. Open a published collection's Theme + Widgets page — for the root collection, `/ThemeAndWidgets.xhtml?id=1`.
3. Click the "Widgets" tab.
4. Observe the "Dataverse Search Box" and "Dataverse Listing" sections, each with a textarea holding the embeddable `<script>` snippet, and a "Done" button.

## New frontend behavior

There is no widgets tab, route, component or i18n string in the SPA. The collection Edit dropdown has a single "Theme + Widgets" item, and it is wired to the shared not-implemented handler (`onClick={handleNotImplementedClick}` in `EditCollectionDropdown.tsx`), so both halves of the legacy page — theme and widgets — are unreachable. Searching the frontend for "widget" finds only the dataset-level "Thumbnails + Widgets" menu entry and the unrelated file-uploader strings.

### Steps to reproduce

1. Log into the modern frontend (http://localhost:8000/modern) as `dataverseAdmin`.
2. Navigate to the root collection at `/modern/collections/root`.
3. Click the "Edit" dropdown and select "Theme + Widgets".
4. Observe the "Not Implemented" modal. No widgets tab or embed code is offered anywhere in the SPA.

## Expected behavior

A collection administrator should be able to obtain the widget embed snippets from the SPA: a search-box snippet and a collection-listing snippet for a published collection, each easy to copy, and an equivalent explanation for an unpublished collection stating that publishing is required first.

## Current behavior

Absent. The SPA has no widgets UI; the only entry point opens the generic "Not Implemented" modal, whose only remedy is a link back to the legacy JSF page.

## Acceptance criteria

- [ ] A collection administrator can reach a widgets view for a collection from the SPA
- [ ] For a published collection it presents the Dataverse Search Box and Dataverse Listing embed snippets, matching the legacy `widgets.js` URLs (correct `alias`, `dvUrl`, `widget` and `heightPx` parameters)
- [ ] Each snippet is easy to copy (for example a copy-to-clipboard control) rather than requiring manual selection
- [ ] For an unpublished collection it explains that the collection must be published first, instead of showing unusable snippets
- [ ] Covered by an automated test asserting the published and unpublished states render correctly
