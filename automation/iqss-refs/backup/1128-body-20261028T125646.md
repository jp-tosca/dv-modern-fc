## Summary

Legacy JSF gives a dataset editor a "Thumbnails + Widgets" page with two tabs: **Thumbnail**, where the dataset's preview image is uploaded, selected from one of the dataset's own image files, or removed; and **Widgets**, which hands out embed code for a dataset citation widget and a full dataset widget. In the new frontend the dataset Edit menu still lists "Thumbnails + Widgets", but the entry is wired to the shared not-implemented handler, so neither tab is reachable.

## Legacy JSF behavior

`dataset-widgets.xhtml` renders the two tabs. The **Thumbnail** tab shows the current thumbnail (or "Default Icon"), an "Upload Image" control (JPG/PNG, max 500 KB, 140x140 display), a "Remove" button once a thumbnail is set, a "Select Available File" control when the dataset contains image files, and Save Changes / Cancel. The **Widgets** tab, for a published dataset, shows copyable `<script src=".../widgets.js?persistentId=...&widget=citation...">` and `widget=iframe` snippets.

### Steps to observe

1. Log into the legacy JSF app (http://localhost:8080) as `dataverseAdmin`.
2. Open a dataset, then Edit Dataset -> "Thumbnails + Widgets" (or `/dataset-widgets.xhtml?datasetId=<id>`).
3. On the **Thumbnail** tab, upload a JPG/PNG and observe the preview plus the "Remove" button appearing, with Save Changes / Cancel below.
4. Switch to the **Widgets** tab and observe the Dataset Citation and Dataset embed snippets.

## New frontend behavior

`EditDatasetMenu.tsx` lists "Thumbnails + Widgets" as `EditDatasetMenuItems.THUMBNAILS_PLUS_WIDGETS`, and its handler is:

```tsx
if (eventKey === EditDatasetMenuItems.THUMBNAILS_PLUS_WIDGETS) {
  showModal()
  return
}
```

`showModal` comes from `useNotImplementedModal`, so the entry opens the "Not Implemented" modal. There is no thumbnail-management or dataset-widgets route or component anywhere in the SPA.

### Steps to reproduce

1. Log into the modern frontend (http://localhost:8000/modern) as `dataverseAdmin`.
2. Open a dataset you can edit and open the "Edit Dataset" dropdown.
3. Select "Thumbnails + Widgets".
4. Observe the "Not Implemented" modal. No thumbnail or widget management appears.

## Expected behavior

Selecting "Thumbnails + Widgets" should open a dataset thumbnail-and-widgets view in the SPA equivalent to the legacy page: upload, replace and remove the dataset thumbnail, pick one of the dataset's image files as the thumbnail, save or cancel, and — for a published dataset — obtain the citation and dataset embed snippets.

## Current behavior

The menu entry is present but non-functional — it opens the generic "Not Implemented" modal. The SPA *displays* dataset thumbnails, but offers no way to manage them; the only route is to leave the SPA for the legacy JSF page.

## Acceptance criteria

- [ ] Selecting "Thumbnails + Widgets" opens a dataset thumbnail/widgets view instead of the "Not Implemented" modal
- [ ] A thumbnail image can be uploaded, with the legacy JPG/PNG and 500 KB validation, and replaced
- [ ] A thumbnail derived from one of the dataset's own image files can be selected
- [ ] An existing thumbnail can be removed, with the legacy confirmation when it came from a data file
- [ ] Changes are applied on Save and discarded on Cancel, and the new thumbnail appears on the dataset and in search results
- [ ] For a published dataset, the citation and dataset embed snippets are shown and easy to copy; for an unpublished dataset, the publish-first explanation is shown
- [ ] The entry is only offered to users permitted to edit the dataset
- [ ] Covered by automated tests for uploading, selecting and removing a thumbnail
