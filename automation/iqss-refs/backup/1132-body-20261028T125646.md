## Summary

Legacy JSF gives superusers a "Manage Harvesting Clients" page for configuring OAI-PMH harvesting from remote repositories: a four-step Create Harvesting Client wizard, plus per-client Run Harvest Now, Edit, and Delete actions. The new frontend has no harvesting administration at all — no route, no component, no strings. The only occurrence of "harvest" in the SPA is a *harvested datasets* counter on the homepage metrics block.

## Legacy JSF behavior

`harvestclients.xhtml` lists configured clients with an "Add Client" button. "Add Client" opens a modal wizard: **Step 1 of 4 - Client Information** (Nickname, Source Name, Server Protocol — OAI only, Server URL, Local Dataverse, optional Custom HTTP Header), followed by steps for format, schedule and display, with Next/Previous navigation and Cancel. Existing clients can be run on demand, edited, or deleted.

### Steps to observe

1. Log into the legacy JSF app (http://localhost:8080) as a superuser (`dataverseAdmin`).
2. Open the dashboard and click "Manage Clients" on the Harvesting Clients card, or go to `/harvestclients.xhtml?dataverseId=1`.
3. Observe the "Manage Harvesting Clients" page with the "Add Client" button.
4. Click "Add Client" and observe "Step 1 of 4 - Client Information" with its fields and Next / Cancel controls.

## New frontend behavior

There is no harvesting UI in the SPA. A case-insensitive search for `harvest` across `src/` and `public/locales/` returns only homepage metrics code (`MetricsResults.tsx` rendering `datasets.harvested`, and the Dataverse Hub metric mappers) — nothing for managing harvesting clients. `Route.enum.ts` has no harvesting route, and there is no dashboard to reach one from.

### Steps to reproduce

1. Open the modern frontend (http://localhost:8000/modern).
2. Note there is no dashboard entry for a superuser (see jp-tosca/dv-modern-fc#5).
3. Navigate directly to http://localhost:8000/modern/dashboard/harvesting-clients.
4. Observe the redirect to `/modern/404` — the route is not registered.

## Expected behavior

A superuser should be able to manage harvesting clients from the new frontend: list configured clients with their status and last-harvest results, create a client (nickname, OAI server URL, target local collection, metadata format, schedule, display settings), run a harvest on demand, and edit or delete a client — with the same superuser-only gating as legacy.

## Current behavior

Absent. No route, no component, no i18n strings, no placeholder. The backend already exposes the `/api/harvest/clients` family, so only the UI is missing; administrators must use the legacy JSF page or the API.
