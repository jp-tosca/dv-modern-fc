## Summary

This installation configures curation labels, and the new frontend correctly renders them: the dataset "Publish Dataset" menu shows a "Change Curation Status" submenu listing Author Contacted, Privacy Review, Awaiting Paper Publication, Final Approval and "Remove Current Status". Selecting any of them opens the "Not Implemented" modal instead of applying the status, so a curator cannot set, change or clear a dataset's curation status from the SPA.

## Legacy JSF behavior

With curation labels configured, a curator can set a draft dataset's curation status from the dataset page, change it to another allowed label, or remove it. Legacy reports the outcome ("Curation Status Changed", "Curation Status is now \"{0}\"", "Curation Status Removed") and rejects invalid attempts with specific messages — label not allowed, status unchanged, labeling disabled, or the version already released (status can only be set on drafts).

### Steps to observe

1. Log into the legacy JSF app (http://localhost:8080) as `dataverseAdmin`.
2. Open a **draft** dataset.
3. Set a curation status from the allowed labels, confirm the "Curation Status is now ..." confirmation, then remove it again.

## New frontend behavior

`ChangeCurationStatusMenu.tsx` reads the allowed labels from the `ALLOWED_EXTERNAL_STATUSES` setting and renders one item per label plus "Remove Current Status" — but every item is wired to the same handler:

```tsx
const handleItemClick = (event: React.MouseEvent<HTMLElement>) => {
  event.stopPropagation()
  showModal()   // useNotImplementedModal
}
```

So the submenu is fully populated and looks functional, but each selection opens the "Not Implemented" modal. There is no curation-status history view either.

### Steps to reproduce

1. Log into the modern frontend (http://localhost:8000/modern) as `dataverseAdmin`.
2. Open a draft dataset — this review used `doi:10.5072/FK2/Q9LZAD`.
3. Open the "Publish Dataset" dropdown and hover/open "Change Curation Status".
4. Select any label, for example "Privacy Review".
5. Observe the "Not Implemented" modal; the dataset's curation status is unchanged.

## Expected behavior

A curator should be able to set a draft dataset's curation status to any allowed label, change it, and remove it from the new frontend, with the resulting status visible on the dataset and the legacy rejection cases handled (label not allowed, no change, labeling disabled, version already released). The status history should also be viewable, as legacy records it.

## Current behavior

The submenu is present and correctly populated from configuration, which makes it look implemented, but every option opens the generic "Not Implemented" modal. Nothing is applied and no history is shown. This is more misleading than an absent control, because the labels render correctly.
