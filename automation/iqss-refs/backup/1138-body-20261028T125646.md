## Summary

Collection-scoped custom user Groups let curators bundle users/groups together to assign roles and permissions in bulk. In the SPA, the Edit menu's "Groups" shortcut is present but non-functional, following the same pattern as the "Permissions" shortcut.

## Legacy JSF behavior

Edit -> Groups navigates to a working "Manage Dataverse Groups" page with explanatory content ("Why Use Groups?", "How To Use Groups") and a "Create Group" action.

### Steps to observe

1. Log into the legacy JSF app (http://localhost:8080) as an admin.
2. Navigate to any collection page.
3. Click "Edit" -> "Groups".
4. Observe the working "Manage Dataverse Groups" page with a "Create Group" button.

## New frontend behavior

Edit -> Groups opens the same generic "Not Implemented" modal used elsewhere in the SPA, instead of a groups-management view.

### Steps to reproduce

1. Log into the modern frontend (http://localhost:8000/modern) as the same user.
2. Navigate to the equivalent collection page.
3. Click "Edit" -> "Groups".
4. Observe the "Not Implemented" modal instead of a groups page.

## Expected behavior

Selecting "Groups" from the Edit menu should load a working groups-management view equivalent to the legacy page, including the ability to create a group.

## Current behavior

The menu item exists but only opens the placeholder "Not Implemented" modal - no groups-management UI has been implemented.
