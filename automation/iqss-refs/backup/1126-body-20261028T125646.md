## Summary

Legacy JSF lets a dataset curator manage who can access a dataset and its restricted files: assign and remove roles on the dataset, and — on a separate file-permissions screen — grant or reject file access requests (individually or in bulk), revoke granted access, and review the request history. In the new frontend the dataset Edit menu still shows a "Permissions" submenu with "Dataset" and "File" entries, but both are wired to the shared not-implemented handler, so neither screen is reachable.

## Legacy JSF behavior

Edit Dataset -> Permissions -> **Dataset** opens `permissions-manage.xhtml`, which lists the users and groups with access, their roles, an "Assign Roles to Users/Groups" action and a "Remove Assigned Role" action per row, plus a Roles panel.

Edit Dataset -> Permissions -> **File** opens `permissions-manage-files.xhtml`, which lists restricted files and pending access requests with: Grant Access, Grant All / Grant Selected, Reject All / Reject Selected, Revoke access for an already-granted user, toggles to show deleted files and the access-request history, and a download of the file-permissions history.

### Steps to observe

1. Log into the legacy JSF app (http://localhost:8080) as `dataverseAdmin`.
2. Open a dataset, then Edit Dataset -> Permissions -> Dataset (or `/permissions-manage.xhtml?id=<datasetId>`).
3. Observe the Users/Groups table with "Assign Roles to Users/Groups" and "Remove Assigned Role".
4. Choose Permissions -> File (`/permissions-manage-files.xhtml?id=<datasetId>`) and observe the file-access request and grant controls.

## New frontend behavior

`EditDatasetPermissionsMenu.tsx` renders the submenu and attaches the not-implemented handler to the whole dropdown:

```tsx
<DropdownButton id={`edit-permissions-menu`} title={t('...permissions.title')} onSelect={showModal}>
  {dataset.permissions.canManageDatasetPermissions && (
    <DropdownButtonItem>{t('...permissions.dataset')}</DropdownButtonItem>)}
  {dataset.permissions.canManageFilesPermissions && (
    <DropdownButtonItem>{t('...permissions.file')}</DropdownButtonItem>)}
</DropdownButton>
```

So selecting either "Dataset" or "File" opens the "Not Implemented" modal. There is no dataset-permissions or file-permissions route or component in the SPA.

### Steps to reproduce

1. Log into the modern frontend (http://localhost:8000/modern) as `dataverseAdmin`.
2. Open a dataset you can administer and open the "Edit Dataset" dropdown.
3. Open the "Permissions" submenu and select "Dataset" (then repeat for "File").
4. Observe the "Not Implemented" modal in both cases.

## Expected behavior

A dataset curator should be able to manage dataset role assignments in the new frontend (list, assign, remove) and handle file access requests (grant or reject individually and in bulk, revoke granted access, review and export the request history, and optionally show deleted files) — gated on `canManageDatasetPermissions` and `canManageFilesPermissions` respectively.

## Current behavior

Both submenu entries are present but non-functional — they open the generic "Not Implemented" modal. Dataset access administration requires leaving the SPA for the legacy JSF pages.
